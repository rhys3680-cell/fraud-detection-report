# Fraud Detection Policy Report

IEEE-CIS Fraud Detection 데이터를 활용한 **거래별 최적 대응 정책** 설계·비교 연구.

## 무엇을 하는 프로젝트인가

사기 탐지를 분류 문제가 아니라 **결정 문제**로 다룬다.

> 거래 시점의 맥락 데이터로 사기 확률과 예상 피해 규모를 추정하고, 사기 피해 비용과
> 정상 거래 차단 비용의 균형을 고려해 거래별 최적 대응(승인·추가 인증·보류·차단)을 결정한다.

목표는 AUC 최대화가 아니라 **총비용 최소화**이다.

```
총비용 = 놓친 사기 손실 + 정상 거래 차단 손실 + 검토 인건비 + 인증 마찰 비용
```

## 접근

정책을 사전에 확정하지 않고 **한 칸에 하나씩 요소를 더하는 사다리**로 배열해, 각 요소의
기여도를 분리 측정한다.

| # | 정책 | 답하는 질문 |
|---|---|---|
| P0 | 전건 승인 | 무개입 기준선 |
| P1 | 단순 금액 규칙 | 단순 휴리스틱보다 나은가 |
| P2 | 단일 임계값 차단 | 모델의 순수 기여 |
| P3 | 비용 기반 임계값 | 비용에서 임계값을 유도하면 나아지는가 |
| P4 | + 금액 의존 임계값 | 고액/소액 차등이 가치 있나 |
| P5 | + 보류(검토 예산 제약) | 검토 인력의 한계 가치 |
| P6 | + 추가 인증 | 추가 인증 도입이 정당한가 |

결론은 "이 정책이 최적"이 아니라 **조건부 권고** 형태로 낸다 —
*검토 인력이 확보되면 P5가, 인증 정확도가 Y 이상이면 P6이 최적*.

## 통상적 접근과 다른 두 가지

**1. 클래스 불균형 가중치를 기본값으로 쓰지 않는다.**
확률값이 기대비용 식에 숫자로 직접 들어가므로 원시 출력의 보정이 중요하다. 가중 모델도
독립 보정한 뒤 변별력과 정책 비용을 비교하며, 불균형 비용은 정책 단계에서 명시한다.

**2. 캘리브레이션이 필수다.**
순위만 맞고 값이 틀린 모델은 잘못된 결정을 내린다. raw/isotonic/Platt 선택과 reliability diagram,
그리고 **금액 구간별 ECE**(손실 큰 구간의 보정 확인)를 평가에 포함한다.

## 구조

```
docs/PLAN.md          기획서 — 문제 정의부터 평가지표까지 전체 설계
notebooks/            00 데이터 → 01·02 EDA → 03 검증설계 → 04 피처 → 05 모델 → 06 정책비교
src/frauddetectionreport/
  data.py             로딩, 병합, parquet 캐시
  splits.py           시간 기반 split (고정)
  features.py         피처 변환 (fit/transform 분리)
  costs.py            비용 파라미터 + 행동별 기대비용
  policy.py           P0~P6 정책 함수
  evaluate.py         총비용 집계, Precision@k, 민감도 루프
data/                 (gitignore) 원본 및 중간 산출물
```

비용·정책·평가 로직은 노트북이 아니라 `src/`에 둔다. 여러 노트북이 같은 함수를 공유해야
파라미터 변경 시 결과 불일치가 생기지 않는다.

## 시작하기

```bash
uv sync
uv pip install -e .
```

데이터는 [IEEE-CIS Fraud Detection](https://www.kaggle.com/competitions/ieee-fraud-detection)
에서 받아 `data/raw/` 에 배치한다 (대회 규정 동의 필요).

```
data/raw/
  train_transaction.csv
  train_identity.csv
  test_transaction.csv
  test_identity.csv
```

## 범위

본 연구는 사기 탐지 **시스템 구축**이 아니라 그 시스템의 **의사결정 계층을 오프라인에서
설계·검증**하는 것이다. 실시간 서빙, 계정·기기 그래프 분석, 검토 피드백 루프는 데이터
제약상 다루지 않으며, 그 이유와 함께 보고서 마지막 장에서 서술한다.

자세한 내용은 [docs/PLAN.md](docs/PLAN.md) 참조.
